## 3. カテゴリ置換ロジック

### 3.1 全体置換（Lv1でフィルタ）

対象: ①、③（smile, naibujimu一部）、④、⑤、⑥

```
処理:
1. ベースファイルから該当カテゴリ（Lv1=X）の行を削除
2. 修正前ファイルの全行を該当位置に挿入
3. 「選択肢の全体像...」行は最後尾に維持
```

### 3.2 部分置換（Lv1+Lv2でフィルタ）

対象: ②（少額払い・簡易払い）、③（相続_預金、内部事務_預金）

```
処理:
1. ベースファイルから該当部分の行を削除
   - souzoku: Lv1=預金 AND Lv2=少額払い・簡易払い
   - naibujimu: Lv1=預金 AND Lv2=普通預金・貯蓄預金
2. 修正前ファイルの全行を該当位置に挿入
3. 他のLv2（払戻し手続き等）は維持される
```

### 3.3 全体ファイル置換

対象: ③（torikaku-bot）

```
処理:
1. 修正前ファイルをそのまま使用（104行）
2. 「選択肢の全体像を見たい方はこちら」行を最新マージ版から追加（必須）
3. 合計105行になる

注意: 修正前ファイルには「選択肢の全体像」行が含まれていない
```

## 4. 処理手順

### Phase 1: 準備

1. 現在のDBソースファイルをバックアップ
   ```
   reference/scenario/ → reference/scenario_backup_{date}/
   ```

2. 出力ディレクトリを確認
   ```
   reference/scenario/ を空にする（またはrev*ファイルのみ削除）
   ```

### Phase 2: カテゴリマージ処理

各改定について以下を実行:

1. **ベースファイルを読み込み**
   - 最新マージ版シナリオから該当ボットのファイルを読み込み

2. **カテゴリを置換**
   - 修正前ファイルで該当カテゴリを置換
   - 複数カテゴリの場合は順次適用

3. **列を整理**
   - 文字数列を削除
   - シナリオパス列を削除
   - Lv1〜Lv10のみ残す

4. **空行を削除**
   - Lv1が空の行を削除（空行問題対策）

5. **ファイルを保存**
   - `reference/scenario/revXX{bot}_シナリオデータ_{date}.xlsx`

### Phase 3: 検証

1. **行数チェック**
   - 生成ファイルの行数が妥当か確認

2. **カテゴリチェック**
   - 各カテゴリが正しく含まれているか確認

3. **差分レポート**
   - 既存DBソース（バックアップ）との差分を出力

### Phase 4: DB再構築

1. ベクトルDBを削除
   ```bash
   # rev*ディレクトリを削除
   rm -rf reference/vector_db/rev*/
   ```

2. タイムスタンプをリセット
   ```bash
   python scripts/rebuild_before_scenario_db.py
   ```

3. DB再構築を実行

## 6. ロールバック手順

問題が発生した場合:

1. バックアップからDBソースを復元
   ```
   reference/scenario_backup_{date}/ → reference/scenario/
   ```

2. DB再構築を再実行

## 7. 推奨実装方法

### オプション A: 自動化スクリプト（推奨）

**メリット**:
- 再現可能
- ドライラン機能で事前検証可能
- 差分レポート自動生成

**スクリプト機能**:
1. `--dry-run`: 実際のファイル作成なしで処理内容を表示
2. `--validate`: 生成後の検証を実行
3. `--diff`: 既存ファイルとの差分を表示
4. `--revision X`: 特定の改定のみ処理

### オプション B: 手動実行

**メリット**:
- 各ステップで確認可能
- 問題発生時に即座に停止可能

**デメリット**:
- 時間がかかる
- ヒューマンエラーの可能性
