# 変更前シナリオファイル生成計画

## 概要
最新のマージ版シナリオに対して、各6回の事務改定の「修正前」データを適用し、変更前状態のシナリオファイルを作成する。

## 目的
ベクトル検索の評価用データ作成：変更後シナリオと比較して、影響範囲候補を正しく検索できているか確認できるようにする。

## 追加要件: 差分ファイルの作成

各事務改定フォルダ配下に、変更点を記した差分ファイル（Markdown）を作成する。

### 差分ファイルの内容

1. **メンテ台帳からの情報**
   - 変更内容（行番号含む）
   - 修正種別、WF通番、事務改定実施日
   - 対象ボット・カテゴリ

2. **シナリオ前後比較からの実際の差分**
   - 修正前/修正後フォルダのシナリオを比較
   - 変更された行の具体的な内容（Before/After）
   - 追加・削除・変更の種別

### 出力例

```

├── ①DC→MDCメンテ台帳43.44.45/
│   ├── 変更点サマリー.md          ← 新規作成

├── ②AMLフィルター→GPLEXメンテ台帳41.42/
│   ├── 変更点サマリー.md          ← 新規作成
```

## 実装アプローチ

### 1. カテゴリ置換ロジック

マージ版シナリオの「Lv1」列（場合によりLv2も）でマッチングし、該当行を修正前ファイルの内容で丸ごと置換する。

**マッチングパターン**:
1. **Lv1のみ**: カード関連, 喪失, 諸届, 預金関連 など
2. **Lv1+Lv2**: 預金 > 普通預金・貯蓄預金、預金 > 少額払い・簡易払い
3. **複数Lv1**: torikaku-bot は全カテゴリ置換

### 2. 処理フロー

```
1. 設定ファイルで改定→ボット→修正前ファイルの対応を定義
2. 各改定ごとにループ:
   a. 対象ボットごとにループ:
      i.   マージ版シナリオを読み込み（pd.read_excel）
      ii.  該当する修正前ファイルを特定
      iii. Lv1/Lv2でマッチングキーを抽出
      iv.  該当カテゴリの行を修正前ファイルの内容で置換
      v.   結果をExcelファイルとして保存
3. 処理結果のサマリー出力
```

### 3. 列の整合性処理

- 修正前ファイルには「シナリオパス」列がない場合がある
- マージ版の列を基準に、不足列はNoneで補完
- 置換対象外の列（シナリオパス等）はマージ版の値を維持

## 実装手順

### Step 1: 設定定義ファイル作成

`config/revision_mapping.py` に改定マッピングを定義

### Step 2: 差分ファイル生成機能

- メンテ台帳からの情報抽出（No.、変更内容、ボット、カテゴリ）
- 修正前/修正後シナリオの比較処理
- Markdownファイル出力

### Step 3: 置換ロジック実装

- get_matching_key(): 修正前ファイルからマッチングキー抽出
- replace_category(): カテゴリ単位の置換処理
- align_columns(): 列整合性の処理

### Step 4: メイン処理実装

- generate_all(): 全改定・全ボットを処理
- generate_one(): 1つの改定・ボットを処理
- generate_diff_summary(): 差分ファイル生成
- validate_replacement(): 置換前の検証

### Step 5: 検証・テスト

- 生成ファイルの行数確認
- 置換されたカテゴリの内容確認
- 置換されていないカテゴリがマージ版のままか確認
- 差分ファイルの内容確認

## 検証方法

### 生成後のチェックリスト
1. [ ] 全10ファイルが正常に生成される
2. [ ] 各ファイルの行数がマージ版と一致
3. [ ] 置換されたカテゴリの内容が修正前ファイルと一致
4. [ ] 置換されていないカテゴリがマージ版のまま

### 手動検証例
```python
# smile-bot の ①DC→MDC を検証
before_df = pd.read_excel('変更前シナリオ/①DC→MDC/変更前シナリオ_smile-bot.xlsx')
original_before = pd.read_excel('①DC→MDCメンテ台帳.../修正前/カード関連/シナリオ_...')
merged_df = pd.read_excel('シナリオ/マージ版シナリオ_smile-bot.xlsx')

# カード関連部分が修正前と一致するか
card_rows = before_df[before_df['Lv1'] == 'カード関連']
assert card_rows.equals(original_before)  # 列調整後

# 預金関連部分がマージ版と一致するか
deposit_rows = before_df[before_df['Lv1'] == '預金関連']
merged_deposit = merged_df[merged_df['Lv1'] == '預金関連']
assert deposit_rows.equals(merged_deposit)
```

## 影響を受けないボット×改定の扱い
スキップ（ファイル作成しない）。理由：
- 最新版と同一のため評価において無意味
- ディスク容量の節約
- 処理対象の明確化
