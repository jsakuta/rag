## 1. 概要

本PoCでは Azure Cosmos DB（Serverless）を使用し、以下の3コンテナでデータを管理する。

| コンテナ名 | パーティションキー | 用途 | Indexer対象 |
|-----------|-----------------|------|-----------|
| `scenarios` | `/categoryId` | シナリオ（業務フロー）データ | ✓（Indexer A: scenarios用） |
| `faqs` | `/categoryId` | FAQ（問い合わせ履歴）データ | ✓（Indexer B: faqs用） |
| `impactAssessments` | `/searchId` | 影響評価結果（Bot書き込み用） | ✗（検索インデックス不要） |

**データベース名:** `maintenance-db`
**エンドポイント:** `https://cosmos-maintenance-poc.documents.azure.com:443/`

※ データフローの詳細は要件定義書（REQ-FAQ-IMPACT-002）セクション7.3を参照

## 2. scenarios コンテナ スキーマ

```typescript
interface ScenarioDocument {
  // --- AI Search 連携フィールド ---
  id: string;                    // "scenario-{categoryId}-{4桁連番}" e.g. "scenario-smile-0001"
  dataType: "scenario";          // AI Search フィルタ用（固定値）
  categoryId: string;            // パーティションキー e.g. "smile"
  categoryName: string;          // 表示名 e.g. "スマイル"
  title: string;                 // 階層パス（AI Search title検索フィールド）
  content: string;               // 回答テキスト（AI Search content検索フィールド）
  combinedContent: string;       // ベクトル化対象テキスト（Skillset入力）
  keywords: string[];            // 階層の各要素をキーワード化
  updatedAt: string;             // ISO 8601 JST e.g. "2026-02-12T00:00:00+09:00"
  isDeleted: boolean;            // Soft Delete（AI Search 除外用）

  // --- 本番拡張フィールド ---
  path: string;                  // 階層パス（= title と同値、将来のチャットボット連携用）
  order: number;                 // Excel行番号（1始まり）
  isFinalAnswer: boolean;        // true: 末端ノード（子なし）, false: 中間ノード（子あり）
}
```

### フィールド詳細

| フィールド | 型 | 必須 | 説明 |
|-----------|-----|------|------|
| `id` | string | Yes | 一意識別子。`scenario-{categoryId}-{4桁連番}` |
| `dataType` | string | Yes | 固定値 `"scenario"`。AI Search の `dataType` フィルタで使用 |
| `categoryId` | string | Yes | パーティションキー。`smile`, `souzoku`, `naibujimu`, `torikaku` |
| `categoryName` | string | Yes | 日本語カテゴリ名。`スマイル`, `相続`, `内部事務`, `取引時確認` |
| `title` | string | Yes | 階層パス。`/Lv1/Lv2/.../質問` 形式 |
| `content` | string | Yes | 最右非空セルのテキスト（回答） |
| `combinedContent` | string | Yes | ベクトル化対象テキスト（後述のルール参照） |
| `keywords` | string[] | Yes | 階層の各レベルテキストを配列化 |
| `updatedAt` | string | Yes | ISO 8601 形式（JST） |
| `isDeleted` | boolean | Yes | `false`（初期値）。削除時に `true` に更新 |
| `path` | string | Yes | `title` と同値。将来のチャットボット連携用 |
| `order` | number | Yes | Excel行番号（1始まり、ヘッダー除く） |
| `isFinalAnswer` | boolean | Yes | 末端ノード判定（子ノードが存在しない場合 `true`） |

## 5. combinedContent 生成ルール

### シナリオ

```
"分類: {Lv1 > Lv2 > ... > Lv(n-2)} | 質問: {Lv(n-1)} | 回答: {Lv(n)}"
```

- `Lv(n)` = 最右の非空セル（回答テキスト）
- `Lv(n-1)` = 回答の1つ左のセル（質問/選択肢テキスト）
- `Lv1` 〜 `Lv(n-2)` = それより左の階層（分類）

**例:**
- 行: `[Lv1="口座", Lv2="開設", Lv3="本人確認", Lv4="運転免許証の場合"]`
- → `"分類: 口座 > 開設 | 質問: 本人確認 | 回答: 運転免許証の場合"`

### FAQ

```
"質問: {title} | 回答: {content}"
```

**例:**
- title: `"口座開設に必要な書類は？"`
- content: `"本人確認書類2点が必要です。"`
- → `"質問: 口座開設に必要な書類は？ | 回答: 本人確認書類2点が必要です。"`

## 7. isFinalAnswer 判定アルゴリズム

```
現在行が末端ノード（isFinalAnswer = true）の条件:
  次の行以降で、同じ親パスを持ち、かつ現在行より深い行が存在しない

判定手順:
  1. 現在行の最深非空Lvのインデックス（current_depth）を取得
  2. 現在行の親パス（current_depth - 1 まで）を取得
  3. 次の行から順にスキャン:
     a. 同じ親パスを持ち、current_depth より深い行 → 子ノードあり → false
     b. 親パスが異なる行 → このブランチ終了 → ループ終了
  4. 子ノードが見つからなかった → true
```

## 9. AI Search インデックス連携

### インデックス名: `maintenance-search-index`

Cosmos DB の両コンテナから同一インデックスに書き込む（Indexer 2つ構成）。

### Skillset によるベクトル化

- 入力: `combinedContent` フィールド
- モデル: `text-embedding-3-large`（3,072次元）
- 出力: `contentVector` フィールド

### Bot の SELECT フィールド

```
["id", "dataType", "categoryId", "categoryName", "title", "content", "order"]
```

新フィールド（`path`, `isFinalAnswer`, `tags`）は AI Search インデックスに存在するが、Bot が SELECT しなければ返却されない（将来の機能拡張用）。

**注記:** `tags` フィールドは **FAQ 専用**である。シナリオデータには `tags` フィールドは存在しない（セクション2参照）。インデックス上では両タイプのドキュメントが同一インデックスに格納されるが、Indexer B（faqs用）のフィールドマッピングでのみ `tags` を設定する。

## 11. 差分ベクトル化（Incremental Vectorization）

Cosmos DB のデータ変更は、Indexer の High Water Mark 方式により差分検知される。変更されたドキュメントのみが再ベクトル化され、全件再処理は行われない。

### 変更検知の仕組み

1. Cosmos DB はドキュメント書き込み（作成・更新）時に `_ts`（Unix タイムスタンプ）を自動更新する
2. データソース定義（`cosmos-scenarios-ds`, `cosmos-faqs-ds`）に `HighWaterMarkChangeDetectionPolicy` を設定済み
3. Indexer は前回実行時の `_ts` 最大値を記録し、次回実行時には `_ts > 記録値` のドキュメントのみ取得する
4. 変更分のドキュメントのみ Skillset（`AzureOpenAIEmbeddingSkill`）に渡され、`contentVector` が再生成される
5. 未変更のドキュメントは処理をスキップ（Azure OpenAI API 呼び出しなし、RU 消費なし）

### データ投入パスと Indexer 連携

| データ種別 | 投入方式 | Cosmos DB 更新 | Indexer 検知 |
|-----------|---------|---------------|-------------|
| シナリオ | 管理Bot → Excel → JSON → upsert | `_ts` 自動更新 | 次回実行時（最大10分後） |
| FAQ | リアルタイム蓄積 → upsert | `_ts` 自動更新 | 次回実行時（最大10分後） |
| FAQ論理削除 | Bot → `isDeleted: true` に更新 | `_ts` 自動更新 | Soft Delete 検知 → インデックスから除外 |

### Indexer 実行間隔

10分（`PT10M`）。Azure AI Search Basic SKU の最短間隔。日次〜時次の差分ベクトル化で運用上十分であり、リアルタイム同期は不要。

## 12. Excel 出力用データ参照（FR-015）

FR-015（シナリオ要修正 Excel 出力）では、Bot が検索結果のシナリオデータをカテゴリ別に Excel ファイルとして出力する。

### 参照元

Bot は検索時に AI Search から取得済みのシナリオデータ（メモリ上のキャッシュ）を使用する。Excel 出力時に Cosmos DB への追加クエリは発生しない。

### カテゴリ別分割ルール

検索結果のシナリオを `categoryId` でグループ化し、カテゴリごとに1ファイルを生成する。

| 条件 | 動作 |
|------|------|
| 検索結果に複数カテゴリが含まれる場合 | カテゴリ数と同じファイル数を生成 |
| 検索結果に1カテゴリのみの場合 | 1ファイルのみ生成 |

### Excel 列マッピング

タイトル文字列（`title`）を `parseTitlePath()` で `/` 区切りの階層配列に分解し、各レベルを個別の列に展開する。最大階層数はカテゴリ内の全シナリオから動的に決定する。

| Excel 列 | データソース | 内容 | 備考 |
|----------|------------|------|------|
| Lv1 | `parseTitlePath(title)[0]` | 第1階層テキスト | — |
| 文字数 | — | `=LEN(A{行番号})` | LEN数式（自動算出） |
| Lv2 | `parseTitlePath(title)[1]` | 第2階層テキスト | 該当なしの場合は空欄 |
| 文字数 | — | `=LEN(C{行番号})` | LEN数式（自動算出） |
| ... | ... | ... | LvN まで繰り返し |
| LvN | `parseTitlePath(title)[N-1]` | 第N階層テキスト | — |
| 文字数 | — | `=LEN(...)` | LEN数式（自動算出） |
| 回答 | AI Search 検索結果 `content` | 回答テキスト（全文） | 切り詰めなし |
| 文字数 | — | `=LEN(...)` | LEN数式（自動算出） |

**列構成例（最大4階層の場合）:**

```
Lv1 | 文字数 | Lv2 | 文字数 | Lv3 | 文字数 | Lv4 | 文字数 | 回答 | 文字数
```

**`parseTitlePath()` の動作:**
- `title` を `/` で分割し、先頭・末尾の空文字を除去
- null/undefined/空文字の場合は `["(空)"]` を返す

### ハイライトルール

ステータス列は設けず、要修正行は行全体の背景色で表現する。

| 条件 | 背景色 | ExcelJS 設定 |
|------|--------|-------------|
| 要修正 ID リストに含まれる行 | 黄色 | `fill: { type: 'pattern', pattern: 'solid', fgColor: { argb: 'FFFFFF00' } }` |
| その他の行 | 白（デフォルト） | 設定なし |

### ファイル生成

| 項目 | 内容 |
|------|------|
| ライブラリ | ExcelJS（インメモリ生成、`writeBuffer()` でバイナリ化） |
| ファイル名 | `scenario_{categoryId}_{categoryName}_{YYYYMMDD_HHMMSS}.xlsx`（JST） |
| ファイル名例 | `scenario_smile_スマイル_20260217_143022.xlsx` |
| ファイル名サニタイズ | `categoryName` のファイル名禁止文字（`\/:*?"<>\|`）は `_` に置換 |
| 送信方式 | SharePoint Online アップロード + Adaptive Card リンク送付 |
