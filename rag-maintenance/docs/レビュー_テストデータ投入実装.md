### 2-C. 残存リスク・注意事項（要引き継ぎ）

| # | カテゴリ | 内容 | 影響度 | 対応案 |
|---|---------|------|--------|--------|
| R1 | **パス依存** | `convert-excel-to-json.py` の `RAG_GEMINI_BASE` がローカル絶対パス `C:\VSCode\rag\rag-gemini\data\source` にハードコード | 中 | 顧客環境では修正が必要。手順書に注記済みだが、環境変数化 or コマンドライン引数化を検討 |
| R2 | **削除性能** | `seed-cosmos.ts` の `--clean` モードは1件ずつ順次削除（約21,000件）。Serverless RU と相まって数十分かかる可能性あり | 低 | PoC用途なら許容範囲。本番化時にはバルク削除（ストアドプロシージャ）or コンテナ再作成を検討 |
| R3 | **並列upsert** | `upsertBatch` は100件を `Promise.all` で並列実行。Serverless RU のバーストリミット次第でスロットリングが発生する可能性 | 低 | 個別エラーはcatchしてログ出力済み。スロットリング多発時は BATCH_SIZE を 50 に下げる（手順書トラブルシュートに記載済み） |
| R4 | **短文content** | FAQ に content < 5文字のドキュメントが 112件（"解決済み", "OKです", "済" 等）。Embedding の品質が低くなる可能性 | 低 | 実データなのでスキップ不可。検索結果のランキングで自然に下位になるため実害は少ない |
| R5 | **keywords空** | スマイルFAQ 8,679件はタグ列がなく `keywords: []`。AI Search の keywords フィールドが空になる | 低 | Semantic Ranker の `prioritizedKeywordsFields` にはヒットしないが、テキスト検索 + ベクトル検索でカバーされる。本番化時にタグ付け運用を検討 |
| R6 | **updatedAt固定値** | 全ドキュメントの `updatedAt` が `"2026-02-12T00:00:00+09:00"` で固定 | 低 | PoC用途では問題なし。本番では Excel の日付列（総則FAQには日付列あり）を使用すべき |
| R7 | **Indexer batchSize** | 21,000件 x text-embedding-3-large のベクトル化は Azure OpenAI の TPM リミットに依存 | 中 | Indexer 内蔵リトライで対応可能だが、完了まで十数分〜数十分かかる場合あり。Azure OpenAI のレート制限を確認しておく |
