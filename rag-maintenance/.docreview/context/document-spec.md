# Document Review Specification

## Review Target
3文書間の整合性レビュー（クロスドキュメント検証）

| 文書 | 役割 |
|------|------|
| docs/要件定義書.md | システムの要件（機能・非機能・データ・インターフェース）を定義 |
| docs/検索設計書.md | 検索アーキテクチャの設計詳細（パラメータ・チューニング経緯） |
| docs/導入手順書.md | ゼロからの環境構築手順（14ステップ） |

## Review Focus: Cross-Document Consistency

### 要件定義書 ↔ 導入手順書
- リソース構成（SKU、命名規則）の一致
- 機能要件で言及される技術要素が手順書に含まれているか
- 環境変数・設定値の整合性
- コスト表の整合性
- セキュリティ要件（認証方式、ロール付与）の一致

### 要件定義書 ↔ 検索設計書
- データ構成（フィールド名、型、件数）の一致
- 検索方式の記述一致（ハイブリッド検索、RRF、Semantic Ranker）
- インデックス設計の整合性
- パラメータ値の一致

### 導入手順書 ↔ 検索設計書
- 手順書のパラメータ参照が設計書と一致するか
- Indexer設定・Skillset設定の整合性
- アーキテクチャ図やデータフローの一致

### 各文書内の一貫性
- 用語の統一（同じ概念に異なる名称を使っていないか）
- 数値の一貫性（件数、サイズ上限、タイムアウト等）
- 参照の整合性（図番号、ステップ参照、注記参照）

## Review Rules
- **確信度の高い指摘のみ**: 曖昧な指摘は避け、具体的な矛盾箇所を引用する
- **False Positive 防止**: 「異なる表現だが同じ意味」のケースは問題として報告しない
- **文書の役割を考慮**: 要件定義書は「何を」、検索設計書は「どう検索するか」、導入手順書は「どう構築するか」。抽象度の違いは矛盾ではない
- **数値の厳密照合**: 件数、SKU、パラメータ値、コスト等は厳密に照合する
